Site Check

Claude Code

Small companies rarely know whether their website or email can be faked or broken into, and nobody checks for them.

  • DoesChecks a website from the outside (HTTPS, security headers, cookies, page code, fake-email protection, known attacks) and lists each problem with the evidence, the fix and how to retest it
  • ResultAn old nginx with HTTP/2 on: flagged for the November 2026 nginx2shell holes in seconds, with the upgrade to make and how to confirm it
  • Tested48 lab sites with 75 problems planted on purpose: 75 of 75 found, 0 false alarms. On real sites it agrees with Mozilla's scanner on 184 of 192 checks
  • SafeguardPassive checks only: nothing is logged in to or attacked, and leaked files are looked for only after the owner proves the site is theirs
  • Tools usedClaude Code, Python, Streamlit, Mozilla HTTP Observatory, GitHub Actions
Read more

Two layers: Site Check's own checks, then Mozilla HTTP Observatory as a second opinion, with every disagreement explained. Anything borderline, or that a passive check can't decide, goes under "Worth a closer look" with how to test it by hand, instead of being counted as a problem. It also looks for the year's known attacks, such as PHP2Shell and the nginx HTTP/2 holes. A daily job compares new actively exploited holes (the CISA list) with the technology each site runs. The client dashboard is a demo: an invented company and its 12-week history, with today's findings from a real check of a test-lab site.
